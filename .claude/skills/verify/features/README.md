# Blocklore feature map

`../features.json` is generated by `featuremap` and never edited by hand. The
files here hold the recipes. Each one declares the ids it covers in a
`<!-- covers: -->` line, and `featuremap check` fails when an id has no recipe or
a recipe covers an id that no longer exists.

## Preconditions

- The site launched per ../SKILL.md on port 3721, rendering the committed `knowledge/` (the
  examples use the halvings-and-supply topic and run `2026-11-20-seed-halvings-and-supply`; any
  published topic, claim or run works).
- Never drive: `pnpm review approve|reject` (only the owner decides), `brain publish` with commit
  outside a real run, `brain research` without need (it spends money), or a production deploy
  just to test (deploys are real; `tools/deploy.sh --check` is read-only).

## Proof rules

- Drive the path a user takes. Mocks count only at a boundary production also has
  (a third-party API), never around the code being checked.
- A recipe lists every entry point. Proving one convenient entry point does not
  prove the others.
- An unreachable entry point is reported with its missing precondition. It is not
  counted as verified.

## Areas

- [home](home.md): the Brain view at `/`: what Blocklore is in plain words, the brain live (now, today, lately, next), what it knows, and the app's bar (modes and Connect), panel and scene.
- [scene](scene.md): the persistent 3D scene of the store beside every view: its views (brain, knowledge, topic, claim, timeline, security, proof), the live feed's animations, drag, zoom, hover and click, reduced motion and the no-WebGL drawing.
- [topics](topics.md): a topic page with the depth dial, claims and ladder; `/topics` redirects to `/`.
- [claims](claims.md): a claim's page: evidence, reader commands, history and record.
- [timemachine](timemachine.md): any topic or claim as Blocklore stated it at a past block height or UTC date: the `/at/<moment>` pages, every topic at `/topics/at/<moment>`, `?at=` on the API and `at` on the MCP tools.
- [changes](changes.md): the change log, the corrections log, the Atom and RSS feeds.
- [progress](progress.md): each month's work counted from the public record, and the reach counts behind it (the proxy and the MCP route).
- [pulse](pulse.md): the chain now from two explorers, BIP status moves, recent changes and the upstream wire.
- [security](security.md): the threat map at `/security`, a threat's page, the watches, the lab's run on each maintained Bitcoin Core release, advisories, and the `threats` and `watches` MCP tools.
- [proposals](proposals.md): the proposal tracker, the version bits blocks set this difficulty period (`/proposals#version-bits`, `GET /api/v1/signaling`, the `signaling` tool, `pnpm brain signaling`), the full BIP index, and a page per BIP (`/proposals/<n>`, its API answer and `get_bip`).
- [debates](debates.md): debate maps at `/debates` and `/debates/<slug>`, their rules, how the brain checks, holds and publishes them, the topic rail link, `GET /api/v1/debates[/<slug>]` and the `debates` tool.
- [api](api.md): the read API, search, the JSON Lines export and llms.txt.
- [mcp](mcp.md): the Model Context Protocol server, its twelve read-only tools, and `/connect`, where readers bring their own model.
- [queue](queue.md): reader suggestions: the box on `/gaps`, `POST /api/v1/queue` with `{"q"}`, triage and `pnpm brain queue`.
- [problems](problems.md): reader reports: "Report a problem" on every claim, `POST /api/v1/claims/<id>/reports`, the hourly recheck, outcomes on the claim, under Corrections and in `GET /api/v1/reports`, the admin's Reader reports and `pnpm brain reports`.
- [loop](loop.md): the timers, `brain tick`, and the daily recheck with its public failures.
- [gaps](gaps.md): the gap map at `/gaps`, `pnpm brain gaps`, how research picks its next topic, and the owner's golden-set bench (`pnpm brain bench`).
- [verify](verify.md): snapshots, their OpenTimestamps proofs, /verify and the verifier script.
- [log](log.md): the research log and one run's page.
- [about](about.md): how Blocklore works, and the rule documents rendered from the repo.
- [meta](meta.md): icons, favicon, share image, manifest, robots and sitemap.
- [exports](exports.md): the `@blocklore/core` library entry points.
- [store](store.md): validating and compiling `knowledge/`.
- [brain](brain.md): checks, research, publish, ingest and the subscription usage.
- [review](review.md): the owner's review queue.
- [admin](admin.md): the owner's console at `/admin`, its sign-in, and the commands it sends the brain.
- [nostr](nostr.md): the Nostr channel people follow: its key and NIP-05, the notes code builds, the screen, the owner's switch and preview in the admin, the Follow link.
- [tools](tools.md): deploy, screenshots, favicon and the style check.
- [mirror](mirror.md): a production mirror from a fresh clone with no environment, `tools/mirror-update.sh` keeping it current, and `pnpm mirror:check` proving it serves the same store as the origin (MIRROR.md).

## Entry contract

Each area file has: an H1, a one-line summary, a `<!-- covers: ids -->` line, then
exactly these sections: `## Sub-features`, `## How to reach it`, `## How to check
it`, `## Gotchas`. Keep it short enough to run without reading source. Split a
file once a section needs its own preconditions.

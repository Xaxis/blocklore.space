# Blocklore feature map

`../features.json` is generated by `featuremap` and never edited by hand. The
files here hold the recipes. Each one declares the ids it covers in a
`<!-- covers: -->` line, and `featuremap check` fails when an id has no recipe or
a recipe covers an id that no longer exists.

## Preconditions

- The site launched per ../SKILL.md on port 3721, rendering the committed `knowledge/` (the
  examples use the halvings-and-supply topic and run `2026-11-20-seed-halvings-and-supply`; any
  published topic, claim or run works).
- Never drive: `pnpm review approve|reject` (only the owner decides), `brain publish` with commit
  outside a real run, `brain research` without need (it spends money), or a production deploy
  just to test (deploys are real; `tools/deploy.sh --check` is read-only).

## Proof rules

- Drive the path a user takes. Mocks count only at a boundary production also has
  (a third-party API), never around the code being checked.
- A recipe lists every entry point. Proving one convenient entry point does not
  prove the others.
- An unreachable entry point is reported with its missing precondition. It is not
  counted as verified.

## Areas

- [home](home.md): the front page, its numbers, pipeline, topic cards and latest changes.
- [topics](topics.md): the topics index and a topic page with the depth dial, claims and ladder.
- [claims](claims.md): a claim's page: evidence, reader commands, history and record.
- [changes](changes.md): the change log, the corrections log, the Atom and RSS feeds.
- [pulse](pulse.md): the chain now from two explorers, BIP status moves, recent changes and the upstream wire.
- [proposals](proposals.md): the proposal tracker and the full BIP index.
- [api](api.md): the read API, search, the JSON Lines export and llms.txt.
- [log](log.md): the research log and one run's page.
- [about](about.md): how Blocklore works, and the rule documents rendered from the repo.
- [meta](meta.md): icons, favicon, share image, manifest, robots and sitemap.
- [exports](exports.md): the `@blocklore/core` library entry points.
- [store](store.md): validating and compiling `knowledge/`.
- [brain](brain.md): checks, research, publish, ingest and the budget.
- [review](review.md): the owner's review queue.
- [tools](tools.md): deploy, screenshots, favicon and the style check.

## Entry contract

Each area file has: an H1, a one-line summary, a `<!-- covers: ids -->` line, then
exactly these sections: `## Sub-features`, `## How to reach it`, `## How to check
it`, `## Gotchas`. Keep it short enough to run without reading source. Split a
file once a section needs its own preconditions.
